### 裁剪与小图案识别验证（2026-10-16，死亡重构前）

调研依据：[OpenCV 模板匹配](https://docs.opencv.org/4.13.0/df/dfb/group__imgproc__object.html)提供局部滑窗与归一化相关性；[阈值处理](https://docs.opencv.org/4.13.0/d7/d1b/group__imgproc__misc.html)用于比较文字分割方案。当前面板没有旋转/透视变化的证据，因此采用有限平移搜索与局部亮度分割，不引入全图仿射配准或新的推理模型。

实现：OBS 采样上限由 1600 提升至 2560 宽，定位继续使用 1600 宽画面；数字/威能从保留的高分辨率帧裁剪，坐标映射后才取整（超过 2560 宽的来源仍会缩小）。头像失败时搜索 ±1 像素，仍使用人物前景掩码和原接受阈值；大招勾号搜索邻域，阈值保持 0.8。低置信度数字使用多阈值一致性复核，补充局部对比度分割，并拒绝将极窄竖线横向拉宽后认作 8。死亡圆环扩大拟合的实验引入了新误判，未采用。威能模板、相似度阈值和状态确认规则未改变。

### Tab 生存状态与英雄重构（2026-10-16）

原错误链路：宽环带内的零散边缘被当成死亡圆环，正常白色头像被误判死亡；状态层随后按死亡规则保留历史英雄，阻止换英雄更新。另有真实死亡动画尚未出现倒计时数字而被漏掉。

现在的职责分开：

- `native/core/life.cpp` 只检查头像上的圆环径向边缘与初始死亡叉号；不读取英雄 ID、历史状态或队伍色相。
- `Recognizer::face` 独立计算完整人物区域的匹配分数，再合并遮挡证据。明确死亡标志优先；低证据返回未知。删除死亡头像边缘补匹配分支。数字只用于可选倒计时，叉号动画不读成数字。
- `State` 只负责确认及保留历史：死亡保留已确认英雄但不刷新其时间；清晰新头像两次有效观察确认；冷启动死亡不猜英雄。完整匹配分数是相似度，并非校准过的正确概率。

8 张真实游戏原生分辨率面板及人工标注存于 `tests/data/life`，测试逻辑独立为 `native/tests/life_regression.cpp`，覆盖 VICTORIA 白色头像、换 Cassidy、死亡叉号、倒计时、邻行被动画遮挡、死亡保留历史和复活。未缩放面板，只将面板外区域置黑。

| 同源对照 / 回归 | 本次改动前 | 本次改动后 |
|---|---:|---:|
| 58 张原生采集帧、580 行的生存读数与人工标注不一致 | 41 | 0 |
| 上述帧中 VICTORIA 英雄不正确或未读出 | 35 | 0 |
| 后续 10 张回放截图、100 行生存与英雄检查 | 生存 4 处不一致 | 全部符合标注 |
| 54 张面板变体中的英雄 / 生存状态 | 533/540、533/540 | 540/540、540/540 |

580 行含 1 行被相邻死亡动画遮住，期望明确未知，不算认出存活；其余 579 行判定符合标注。108 张维护中的正常头像无误判死亡，360 次换底色英雄检查通过。这些是同一段已保存真实回放的离线检查及模板衍生回归，不是跨比赛、跨设备或新版插件长时间在线准确率；未把预览图缩小当成采集质量。运行证据在忽略目录 `.diagnostics/life-refactor`，关键失败帧已加入可分发源码的固定测试。

### 裁剪坐标审计与面板独立缩放（2026-10-16）

已保留 2560 宽采样、从高分辨率源取图、大招勾号局部搜索、数字多阈值/局部对比度复核及窄字符检查。新增加的校正不调整这些匹配阈值。

之前只用约 26 像素的表头高度估算整张表的比例，并将 24–28 像素厚度归为比例 1；面板相对画布改变 2%–4% 时，行距误差累积，原生输入测试会找不到面板。现在要求两队全部八条内部行分隔线支持布局；初始比例不满足时，通过分隔线联合拟合比例。只接收证据充分的布局，不从局部文字峰值任意挪动单个字段。

新增测试固定画布大小、围绕画布中心缩放面板内容（96%、98%、102%、104%），区别于整张图片改变分辨率。两张原图加八张变体：旧版定位 2/10，校正后 10/10；六项统计和大招共 700 个值均正确。八张变体的定位及数值断言已加入原生回归。原有 54 张变体仍为统计 3234/3240、6 个未知、0 个错值，大招 540/540，英雄及生存各 540/540；360 次头像换底色回归通过。

开发诊断支持直接导出生产识别器实际使用的裁片、矩形及叠框图：

```powershell
.build/Release/owcs-recognizer-test.exe data/models tests/data/life/cassidy-swap.png --inspect .diagnostics/crop-audit/native-cassidy
```

输出 `crops.json`、`overlay.png` 和每个字段的原始裁片，区分原分辨率取样与归一化重试；坐标导出和生产取图共用 `Panel::rect`，不是另写一套近似坐标。诊断不增加公开 API 字段，也不在正常运行中写图。该 2560 宽真实帧的 60 个统计输入矩形无交集，邻列最小间隔为 13 像素；这只能证明这些矩形没有串列，不能单凭矩形间距证明所有画面的字符都完整或 OCR 都正确。

## 字段独立更新（0.5.1）

- 生存分类结果和历史死亡状态不再否决英雄更新；仅当前头像的明确圆环/叉号遮挡使头像观测无效。生存判断仍需可见头像结构作为证据，不能把未检测到圆环直接当作存活。

- 确认未选英雄时清空不适用字段；确认行内选手身份变化时重置该选手，避免串人。这些必要关联保留。
- `native/tests/life_regression.cpp` 使用真实原分辨率面板验证换白色头像、换 Cassidy、死亡叉号、倒计时及复活；每种转换在两次有效观测内确认。另在真实识别结果上注入单字段故障，验证英雄未知/交替、错误死亡标签、单列数字漏读不会冻结其他字段，并覆盖大招就绪到消耗的跳变。

以上是离线真实截图序列和故障注入测试，不是本次新做的实时游戏联测。两次观察表示识别器的有效采样次数，不等于游戏两帧；实际耗时取决于采样频率和处理负载。

## 对齐、姓名和数字发布（0.5.2）

- 网格校准保存完整浮点纵向起点和比例；用八条分隔线的边缘中心共同拟合，避免把双像素边缘平台的任意一侧当作精确行位置。`Panel::rect` 保留浮点计算直到最终源图裁剪取整。已知几何的合成面板覆盖十行实际裁剪，旧实现有四行中心偏差超过 1 像素，新版全部在 1 像素内。
- 姓名图像差异只触发 OCR 复核，不再跳过整行或据此清空数据。复核期间隐藏旧姓名归属，行内观测继续更新；确认相同文本只更新姓名锚点，确认不同文本才切换身份代次并清理旧历史。
- 数字使用独立的 `Confirmation::Nondecreasing` 策略，不设置每次增长 500/3/20 的上限。连续增长由下一次观测确认前一次实际读数，保留前一次置信度及时间；一般增加一个有效采样间隔（默认 5Hz 时约 200ms），不把延迟数据伪装成当前帧。相同读数即时刷新，单次高峰/回落不确认，实际归零或回放跳转需新序列确认。
- `native/tests/state_regression.cpp` 的 125 项审计覆盖快速增长、漏读、错误突增/突降、回放归零、采样中断、姓名持续异常。报告记录输入类型、原始值、期望发布值、实际值及内部更新决策；这些是确定性故障注入测试，不是 125 个实战样本。

## 生存判定统一（0.5.5）

`Recognizer::normalPortrait` 对完整人物区域与中央覆盖区域共同评分，只接受同一模板、同一平移下的双区域一致性；人物掩码继续排除底色。`classifyLife` 统一输出 Alive / Dead / Unknown：正常头像成立时不把人物纹理当死亡标志；正常解释不成立时才依靠明确死亡标志确认死亡，两者均无足够证据则未知。英雄身份仍使用原独立匹配和确认过程，不依赖已发布的生存历史。

## OBS 集成

只对独立便携 OBS 执行，不能指向日常直播实例。准备：

1. 解压独立 OBS 到 `.diagnostics/obs-portable`，使用 `--portable --multi` 启动。
2. 创建名为 `Test` 的场景；打开预览。OBS 自带 WebSocket 设为端口 4457，测试实例关闭认证；不要用于对外服务。
3. 将编译后的插件安装到该目录；插件数据接口设为端口 8766，仅监听本机。
4. 运行 `python scripts/test-obs-integration.py`。脚本创建/删除 Fixture、MediaFixture 测试来源，禁用自动 Tab。

覆盖图片与媒体源、原画面像素不变、HTTP/WS 首帧和后续快照、schema 3.0、多源、暂停/移除、问号与英雄切换、粘连数字与死亡头像。报告输出到被 Git 忽略的 `.diagnostics`。HUD 锁定和 Tab 持键不是公开 API 字段，HUD 算法由原生测试覆盖。

## 发布检查与边界

- 构建和上述检查通过后运行 `scripts/package-plugin.ps1 -SkipBuild`，得到安装包、源码包和 SHA256 清单。
- 安装包只包含插件运行依赖、许可证、使用/API/资源说明及当前 schema；不分发回归图片、旧程序或诊断记录。
- 安装器校验包内文件并备份覆盖内容。发布前校验归档、清单和中文路径安装。
- 自动 Tab 曾在真实游戏及管理员 OBS 中由用户确认生效；当前集成不模拟真实游戏按键。
- 未覆盖所有设备、实体采集卡、HDR、任意字体/语言、超宽屏、赛事横向重排及长时间直播压力。姓名 OCR 可能存在同形字误读。
