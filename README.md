# OWCS OB Analyzer

面向《守望先锋》16:9 自定义房间实时观战画面的轻量顶栏分析器。当前初版只处理两类持续状态：

- 10 个选手槽当前英雄；
- 每个槽位的选手昵称原始 HUD 条和英雄图标；
- 每个选手的存活、阵亡或未知状态。
- 每个选手独立保存英雄确认/切换、阵亡与复活事件时间线。
- 左侧整体时间线保留最近 300 条事件，可按选手和事件类型筛选。

它不会使用双方卡片的红/蓝底色判断队伍，也暂不处理比赛阶段、暂停或击杀事件。英雄识别使用随软件打包的官方插图预生成观战 HUD 模板，以不依赖队伍颜色的边缘特征做确定性匹配；相似度或第一、第二候选差距不足时会保持未知，不会猜测英雄。运行方式仍为实时增量：每个采样周期都读取廉价的生死标记，只有头像画面发生变化、候选尚待确认或轮到低频复核时才重新识别英雄。

## 运行

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[test]"
.\.venv\Scripts\owcs-ob-analyzer
```

底部控制条默认只显示运行状态、开始/停止和浮层显隐控制，选手总览可按需展开。开始识别后，每位选手会在游戏原选手栏下方获得一个独立的高透明时间线浮层；浮层整体鼠标穿透，不会拦截游戏操作。它显示原始昵称条、英雄图标、当前英雄、生存状态和最近两条个人事件，时间从本次开始识别起计算，不使用队伍底色作为识别依据。

昵称当前直接取自对应槽位的 HUD 画面，因此中英文和特殊昵称都能原样显示，也不会把通用中文 OCR 的数秒延迟放进实时识别主循环；结构中已保留独立文本名字字段，后续可接入异步 OCR 用于导出或检索。

## 浮层快捷键

- `F8`：显示或隐藏十名选手浮层和左侧整体时间线；笔记本功能键未发送标准 `F8` 时可用 `Ctrl+Alt+O`；
- `F9`：重新置顶浮层并切换左侧时间线的鼠标交互模式，再按一次恢复鼠标穿透；若系统中已有程序占用 `F9`，启动时会自动注册 `F10`。也可用 `Ctrl+Alt+I`，或直接点击控制条的“操作事件栏”按钮。

快捷键使用只读键盘状态检测，在 Overwatch 获得焦点时仍然生效，也不会拦截或合成游戏输入。左侧面板显示从本次开始识别起计算的当前时间，事件按最新在上排列；进入交互模式后可分别选择选手槽位和英雄确认、英雄切换、阵亡、复活事件。

采集会优先定位 Overwatch 窗口顶部区域；没有发现游戏窗口时才读取主显示器。采集优先使用 DXGI，初始化失败时自动回退 MSS。

无边框模式下，Windows 客户区可以跟随 16:10 显示器保持 `2560×1600`，同时游戏内宽高比仍设为 16:9。本项目按游戏的逻辑 16:9 HUD 高度换算顶栏坐标，不要求 DXGI 客户区本身也是 16:9。

用静态顶栏图验证识别结果：

```powershell
.\.venv\Scripts\owcs-ob-analyzer --image .\tests\data\reference_top.png --json
```

用静态图预览浮窗：

```powershell
.\.venv\Scripts\owcs-ob-analyzer --image .\tests\data\reference_top.png
```

## 当前边界

- 坐标针对标准 16:9 游戏内观战 HUD；窗口化画面必须保持 16:9，且不能裁掉顶栏。
- 初始十名英雄约 3 秒分批完成连续确认；稳定画面只做低频复核，单次误判不会立即覆盖已确认英雄。
- 已确认英雄切换需要 5–7 次连续一致；阵亡到复活需要 5 帧强信号，避免头像动画和死亡特效造成短暂闪烁。
- 阵亡识别以昵称底板压黑为主判据，不依赖双方队伍颜色；结构化血格和阵亡叉只作为存活/缺失名字条时的辅助证据，避免亮地图背景被误判为血条。
- “未知”是正常安全结果。读不到清晰头像或生死标记时，不会强行猜测，也不会清除上一个已确认英雄。
- 当前会自动定位标题中含 Overwatch 的可见游戏窗口；多显示器手动选择和坐标校准属于下一阶段。
