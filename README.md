# OWCS OB Analyzer

实时状态输出接口见 [docs/STATE_API.md](docs/STATE_API.md)。程序默认在
`0.0.0.0:8765` 提供 WebSocket 状态流和 HTTP 当前状态接口。

面向《守望先锋》16:9 自定义房间实时观战画面的轻量顶栏分析器。当前初版处理三类持续状态：

- 10 个选手槽当前英雄；
- 每个槽位已确认的中英文选手 ID、原始 HUD 名字条和英雄图标；
- 每个选手的存活、阵亡或未知状态。
- 每个选手独立保存英雄确认/切换、阵亡与复活事件时间线。
- 左侧整体时间线保留最近 300 条事件，可按选手和事件类型筛选。

它不会使用双方卡片的红/蓝底色判断队伍，也暂不处理比赛阶段、暂停或击杀事件。英雄识别使用随软件打包的官方插图预生成观战 HUD 模板，以不依赖队伍颜色的边缘特征做确定性匹配；相似度或第一、第二候选差距不足时会保持未知，不会猜测英雄。运行方式仍为实时增量：每个采样周期都读取廉价的生死标记，只有头像画面发生变化、候选尚待确认或轮到低频复核时才重新识别英雄。

## 运行

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[test]"
.\.venv\Scripts\owcs-ob-analyzer
```

底部控制条只显示运行状态、采集信息、开始/停止、浮层显隐和退出，不重复展示玩家状态。开始识别后，每位选手会在游戏原选手栏下方获得一个独立的高透明时间线浮层；浮层整体鼠标穿透，不会拦截游戏操作。它显示原始昵称条、英雄图标、当前英雄、生存状态和最近两条个人事件，时间从本次开始识别起计算，不使用队伍底色作为识别依据。控制条的 `×` 会停止采集、关闭全部浮层并退出程序。

选手 ID 使用同一个离线模型识别中文和英文，并在独立后台线程中批量处理十个名字条，不阻塞实时英雄和生存状态循环。原图和彩色转灰度结果必须一致，高置信结果连续三次一致才会发布；低对比度结果需要五次一致。已确认 ID 不会因短暂漏读或单次误识别被清空或替换。原始 HUD 名字条在文字尚未确认时仍会显示。

## 浮层快捷键

- `Ctrl+Alt+H`：显示或隐藏十名选手浮层和左侧整体时间线；
- `Ctrl+Alt+I`：通过 Windows 原生窗口接口重新置顶并激活工具；左侧整体时间线始终可点击。

这两个组合键在 Overwatch 获得焦点时仍然生效。程序不再监听裸 `F8/F9`，避免同时触发游戏或显卡软件的截图快捷键，也不会合成游戏输入。左侧面板始终接受鼠标操作，显示从本次开始识别起计算的当前时间，事件按最新在上排列，并可分别选择选手槽位和英雄确认、英雄切换、阵亡、复活事件。

采集会优先定位 Overwatch 窗口顶部 24% 区域；没有发现游戏窗口时才读取主显示器。采集优先使用 DXGI，初始化失败时自动回退 MSS。分析开始后先在保持现有横向坐标和裁剪尺寸不变的前提下搜索整组顶栏的纵向偏移；结构候选还必须通过多个官方英雄头像模板复核，连续三帧一致后才允许识别和输出。定位失败会暂停新状态确认，不会猜测坐标。

无边框模式下，Windows 客户区可以跟随 16:10 显示器保持 `2560×1600`，同时游戏内宽高比仍设为 16:9。本项目按游戏的逻辑 16:9 HUD 高度换算顶栏坐标，不要求 DXGI 客户区本身也是 16:9。

用静态顶栏图验证识别结果：

```powershell
.\.venv\Scripts\owcs-ob-analyzer --image .\tests\data\reference_top.png --json
```

用静态图预览浮窗：

```powershell
.\.venv\Scripts\owcs-ob-analyzer --image .\tests\data\reference_top.png
```

## 当前边界

- 当前自动定位只修正纵向平移，不改变已经验证的逻辑 16:9 横向坐标、ROI尺寸或16:10无边框适配；输入不能裁掉顶栏。
- 初始十名英雄约 3 秒分批完成连续确认；稳定画面只做低频复核，单次误判不会立即覆盖已确认英雄。
- 已确认英雄切换需要 5–7 次连续一致；阵亡到复活需要 5 帧强信号，避免头像动画和死亡特效造成短暂闪烁。
- 阵亡识别以昵称底板压黑为主判据，不依赖双方队伍颜色；结构化血格和阵亡叉只作为存活/缺失名字条时的辅助证据，避免亮地图背景被误判为血条。
- “未知”是正常安全结果。读不到清晰头像或生死标记时，不会强行猜测，也不会清除上一个已确认英雄。
- 选手 ID 不做模糊纠错，也不使用可能错误的近似名字替换；正式英文 ID 和测试中文 ID 使用相同的双预处理、多帧确认规则。
- 当前会自动定位标题中含 Overwatch 的可见游戏窗口和顶栏纵向位置；多显示器手动选择以及横向/缩放校准不在本阶段范围内。
